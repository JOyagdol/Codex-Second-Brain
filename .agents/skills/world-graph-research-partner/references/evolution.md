# 연구 상태와 스킬의 지속 갱신

사용자가 승인한 연구 협업과 기록 범위에서 [공통 기억 규칙](memory-protocol.md)을 적용한다. 반복되는 같은 범위의 기록에 매번 승인을 재요청하지 않는다.

| 변화 | 기준 저장 위치 |
| --- | --- |
| 연구 목표·범위·방법의 결정, 중요한 가설·보류 | Notion Research State + Decisions |
| 실험 결과·실패·구현 확인 | 실제 run/config/commit + Notion 실험 기록·세션 |
| 논문 분석과 연구 관련성 | 기존 Literature row 내부, 관련 상태에 근거 링크 |
| 재사용할 평가·작성·협업 기준 | Git 스킬 원본과 해당 설치본 |
| 작업 진행·미해결·다음 행동 | AI Sessions |

AI 제안과 사용자 채택을 구분한다. 사용자 보고와 직접 검증을 구분한다. 연구 방향 변경과 새로운 외부 권한을 혼동하지 않는다. 과거 원문·결정을 보존하고 최신 상태에서는 활성/폐기 여부를 분명히 한다.

## 실제 스킬 저장

1. 현재 Git 원본과 설치본을 읽어 충돌을 확인한다. name과 기존 설치 ID를 유지하며 필요한 규칙만 수정한다.
2. 공개 원본에 개인 상태·Notion 식별자·토큰이 섞이지 않는지 확인한다. 공통 파일, 상대 참조, YAML을 검증한다.
3. 사용자가 지정한 원본 저장소에 해당 변경만 commit하고 일반 push 또는 GitHub 도구의 동등한 ref 갱신으로 반영한다. 다른 사용자 작업은 stage하지 않는다. 원격 최신 커밋이 다르면 다시 읽고 병합하며 force push하지 않는다.
4. ChatGPT Work에서 설치 스킬 작업공간이 Git 기반인 경우 호스트 skill-creator 절차대로 같은 설치 ID 경로를 수정·검증·선택 stage·commit·push한다. 그 성공이 ChatGPT 저장 완료다. Codex 사용자 PC는 pull 및 install 적용 성공을 별도로 확인한다.
5. 어느 한 단계가 실패해도 성공한 단계는 사실대로 남기고 같은 버전으로 이어서 처리한다. 저장소 push, ChatGPT 저장, Notion 기록, PC 설치를 각각 구분한다.

이 절차는 대화 밖의 무인 작업, 연구 코드·데이터 임의 변경, 외부 제출·연락을 허가하지 않는다.
