# 문헌 조사와 연구 방향 연결

## 조사 방식

- 현재 결정할 질문을 중심으로 검색하라. 예: 부분 관측 그래프로 방을 구분하는 평가, 2D 이미지와 3D 그래프의 대응, BIM에서 얻을 수 있는 정보의 효과. 기존에 읽은 논문만으로 새로움을 판정하지 마라.
- 사용자가 조사·최신 동향·검증을 요청하거나 논문의 구체적 방법·성능·기여를 판단할 때 원문과 현재 자료를 검색·확인하라. 기본 개념에 대한 짧은 논의는 요청 범위에 맞춰 처리하라.
- 학회·저널 원문, 저자 공개 원고, 공식 프로젝트·저장소를 근거로 사용하라. 검색 요약이나 다른 요약문의 주장을 원문을 읽은 것처럼 표현하지 마라.
- 실제 확인한 제목, 저자·연도·발표처, 링크, 읽은 범위, 근거 위치를 기록하라. abstract만 읽었거나 코드 실행을 하지 않았다면 그 범위를 유지하라. 숫자·표·그림 설명에는 해당 위치와 평가 조건이 필요하다.
- 원문 접근에 실패하면 확인 가능한 내용까지 조사하고 미확인 항목을 남겨라. 핵심 판단이 본문에 달려 있을 때는 필요한 PDF나 특정 페이지를 요청하라. 확인하지 못한 정확도·수식·Figure 번호를 만들지 마라.
- “선행연구가 없다”, “최초다”는 검색으로 자동 확정할 수 없다. 조사 범위 안에서 찾은 가장 가까운 연구와 남은 불확실성을 설명하라.

## 비교해야 할 조건

| 비교축 | 확인할 내용 |
| --- | --- |
| 문제와 출력 | room/scene retrieval, coarse localization, pose estimation, graph generation 또는 alignment 중 무엇인가? |
| 질의 | RGB, RGB-D, 점군, 텍스트, 수작업 그래프 중 무엇이며 GT 정보가 어디까지 주어지는가? |
| 참조 지도 | BIM/CityGML, 재구성·스캔, 다수의 실제·합성 이미지 중 무엇에서 어떤 정보를 얻는가? |
| 객체·관계 | 예측 또는 GT인지, 2D 또는 3D인지, instance 대응이 주어지는지, 부분 관측을 어떻게 처리하는가? |
| 모델과 학습 | hand-crafted score, embedding, GNN 등 실제 방법, supervision·사전학습·미관측 환경의 조건은 무엇인가? |
| 평가 | 데이터·split·후보 풀·정답 단위·지표·시간 범위·실패 질의 처리가 어떻게 되는가? |
| 본 연구와 연결 | 직접 비교군, 구성요소 차용, 평가 설계 참고, 차별성 검토 중 어떤 역할인가? |

문헌이 입증한 내용과 본 연구에 적용할 수 있다는 자신의 추론을 분리하라. 논문의 문제와 목적을 존중하고, 그 논문이 목표로 삼지 않은 CityGML 미사용 등을 곧바로 결함으로 평가하지 마라. 비교 조건이 다르면 성능 수치를 나열하되 직접 우열 비교의 한계를 밝혀라.

## 출발 문헌 선택

현재 프로젝트의 Literature와 Research State를 읽고 관련 문헌을 선택한다. 과거 논문의 개인 검토·novelty 판단은 Notion 이관 기록에 보존되어 있다. 그것을 현재 원문의 검증 결과로 취급하지 않는다.

## 조사에서 실행으로

조사 결과는 핵심 발견과 근거, 본 연구와의 공통점·차이, 가져올 수 있는 방법이나 평가, 남은 가설과 그 검증으로 이어지게 하라. 방향 추천에는 중요한 문헌의 근거를 연결하되 가설을 확정 성과처럼 서술하지 마라.

새 논문을 Background / Baseline / Closest work / Novelty threat / Method inspiration / Future direction 중 관련 역할로 분류하라. 수집 사실보다 현재 가설·방법·실험·원고의 어느 결정을 바꾸는지 설명하라. 하나의 논문이 여러 역할을 가질 수 있으며 DB에 없는 속성을 임의로 추가하지 마라.

여러 방향을 비교할 때는 가장 큰 연구 불확실성을 줄이는지를 중심으로 기여 가능성, 필요한 자원, 구현 부담을 함께 판단하라. 검증 가능한 한 단계와 장기 확장을 구분하라. 단순 검색 요청을 자동으로 대규모 조사나 구현 프로젝트로 확대하지 마라.

## 논문 분석과 Notion Literature 기록

사용자의 기존 논문 분석 저장 선호를 따르라. [기억 위치](memory-location.md)의 프로젝트 설정에서 Literature 목적지를 읽고 실제 스키마를 fetch하라. 사용자가 다른 위치를 지정하거나 저장하지 말라고 하면 현재 요청을 우선하라.

- 실제 기록 전 페이지·데이터베이스·속성 스키마를 읽고 논문 제목·DOI·URL로 기존 row를 확인하라. 별도 독립 페이지를 중복 생성하지 말고 해당 논문 row/page 내부에 상세 분석을 기록하라.
- 상세 분석은 다음 순서를 기본으로 하라: Paper Summary → Problem → Research Gap → Objective → Contributions → Method → Architecture → Dataset/Setup → Experiments → Results → Limitations → Reproducibility → Significance → 우리 연구와 연결점 → Research Opportunities → Questions/Ideas → Next Actions. 근거가 없으면 해당 위치에 미확인 또는 해당 없음과 이유를 남기고 내용을 만들지 마라.
- 기존 Paper, Authors, Year, Venue, Status, Topic, Paper URL, Code URL, BibTeX Key, Input, Map, Output, Gap, Evidence Location, Questions 등 속성과 사용자 작성 내용을 보존하라. 실제 스키마를 우선하고 제공되지 않은 속성 이름·자료형을 가정하지 마라. 논문 주장·검증된 결과·본 연구로의 추론을 구분하라.
- 코드·본문·표·그림의 근거 위치를 연결하되 확인하지 않은 수치나 재현 상태를 채우지 마라. 도구 접근이 막히면 분석은 가능한 범위까지 제공하고 저장하지 못한 점을 알리라. 저장 성공을 확인한 뒤에만 기록 완료를 보고하라.
