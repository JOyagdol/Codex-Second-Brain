# 전문 스킬 간 검토 전달 규약

## 역할 경계

- Research Second Brain: 문제 맥락 유지, 전문 관점 선택, 의견 종합, 다음 행동 제안.
- Research Gap & Positioning Analyst: 선행연구 대비 차별점과 주장 가능한 범위.
- Experiment Designer & Evaluator: 가설을 구분하는 실험과 결과의 해석 범위.
- Paper Architect & Scientific Writer: 근거에 맞는 논문 구조·문장·그림·표.
- Top-Tier Research Reviewer & Defense: 중대한 타당성 문제와 제출 위험 검토.

스킬은 작업 지침이다. 별도의 실행 도구 없이 여러 독립 에이전트가 실제 실행되었다고 표현하지 않는다. 단일 모델에서 역할별로 검토하면 '전문 관점별 교차 검토'라고 설명한다. 실제 위임 기능을 사용한 경우에만 실행된 역할과 읽은 자료를 보고한다.

## 입력 패킷

현재 결정할 질문, 원고/설계/코드의 버전, 사용할 자료, 관측된 결과, 가정, 제약, 열린 쟁점을 함께 전달한다. 중요한 주장에는 C1, C2와 같은 ID를, 근거에는 E1, E2를, 쟁점에는 I1, I2를 붙여 연결할 수 있다.

## 반환 패킷

전문가는 다음 정보를 짧게 반환한다.

| 항목 | 내용 |
|---|---|
| 검토 쟁점 | 무엇을 판단했는가 |
| 판단 | 제안 / 지지 / 반박 / 수정 필요 / 판단 유보 |
| 근거 | 출처와 정확한 위치, 또는 미확인 표시 |
| 중요한 반론 | 자기 제안에 대한 가장 강한 합리적 대안 |
| 판단 변경 조건 | 어떤 관측·실험·문헌이 결론을 바꾸는가 |
| 다음 행동 | 필요한 최소 작업과 완료 기준 |

## 종합 규칙

역할 수나 다수결은 근거의 강도가 아니다. 모든 역할이 동의해도 독립 검증을 받은 것으로 보지 않는다. 관점별 결론을 미리 통일시키지 않으며, 근거가 부족하면 불일치를 유지한다. 비판을 반박하는 문장과 실제로 문제를 해결하는 실험을 구별한다.

일반 요청에는 관련 역할 1~2개를 선택한다. 중대한 선택에는 2~4개 역할을 사용하되, 같은 역할을 재귀적으로 무한 호출하지 않는다. 기본적으로 최초 검토와 수정안 재검토의 두 번이면 멈추고, 추가 자료가 필요하면 '판단 유보 + 필요한 증거'로 종료한다.

출력에는 검토 결과, 근거, 반론, 결정 조건을 제시한다. 실제로 존재하지 않는 회의 발언이나 실행 로그를 만들지 않고, 비공개 사고과정을 대화록처럼 노출하지 않는다.

## 저장과 실행 경계

기본 결과는 현재 대화에 반환한다. Notion, GitHub, Drive, 문서, 일정에 대한 쓰기는 사용자의 명시적 요청 또는 이미 승인된 해당 작업 범위가 있을 때만 수행한다. 스킬을 사용했다는 이유로 다른 스킬의 원본, 연구 방향, 문서, 코드 또는 외부 계정 설정을 자동 변경하지 않는다. 영구 저장을 했다고 보고하려면 실제 쓰기 결과를 확인한다.
