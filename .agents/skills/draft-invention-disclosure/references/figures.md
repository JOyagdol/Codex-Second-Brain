# 도면 작성·간소화 원칙

## 목적부터 선택

| 유형 | 답하는 질문 | 담을 요소 |
|---|---|---|
| 기능 구성도 | 무엇이 연결되어 작동하는가? | 입력, 주요 처리부, 출력, 필요한 저장·질의 연결 |
| 처리 흐름도 | 어떤 순서와 조건으로 처리하는가? | 핵심 단계, 의미 있는 분기, 합류, 종료·제외 경로 |
| 입력–결과 예시 | 이 처리가 구체적으로 무엇을 만드는가? | 간단한 입력, 필요한 중간 상태, 결과 대응 |
| 별도 세부도 | 앞 그림만으로 설명 불가능한 차이가 있는가? | 핵심 구성의 독립적인 설명 가치가 있는 세부 |

추가 설명 가치가 없으면 도면을 늘리지 마라. 전체 흐름과 상세 흐름이 중복되고 한 페이지에서 읽을 수 있으면 통합하라. 통합으로 글자가 작아지거나 분기를 따라가기 어려워지면 분리하라. 도 1·2·3의 역할을 특정 발명에서 가져와 강제하지 마라.

## 그림과 본문의 역할

그림에는 짧은 명사·동사 라벨, 단계 번호, 조건 질문, 예/아니오 경로만 남기는 것을 기본으로 하라. 임계값, 수식 유도, 모든 예외, 구현 함수명은 필요한 경우를 제외하고 본문에 두어라.

간소화하면서 적용 대상을 바꾸지 마라. 예를 들어 ‘1차 검사 후보만 추가 검증’하는 절차를 ‘모든 대상 추가 검증’으로 그리지 마라. 특정 설정을 켠 실시예라면 캡션이나 본문에 명시하고 모든 구현의 필수 절차처럼 나타내지 마라.

조건 탈락 시 후보 해제, 다른 판정으로 이동, 결과 생성 안 함, 원래 판정 유지 중 실제 경로를 구별하라. 모든 쌍에 결과가 생기는 것처럼 출력 상자에 무조건 연결하지 마라. 도면에서 세부 예외를 생략하면 관련 본문과 연결하고 주 흐름의 의미를 훼손하지 마라.

## 표현 방식

- 검정 선과 흰 배경을 기본으로 사용하고 색이 없어도 구별되게 하라. 장식·그라데이션·발표용 아이콘은 피하라.
- 처리 상자와 판정 마름모, 일관된 화살표로 표현하라. 구성도는 데이터 이동과 제어 관계를 혼동하지 않게 하라.
- 한글이 작은 글씨에서도 읽히는 글꼴과 충분한 선 간격을 사용하라. A4에 삽입된 실제 크기로 확인하라.
- 부호·단계 번호를 일관되게 부여하고 본문 참조를 맞춰라. 문서가 이미 부호 체계를 가지면 보존하라.
- 정확한 도면은 SVG·벡터·결정적 드로잉 도구로 만들라. 이미지 생성 모델로 정확한 라벨·분기·수치 도면을 만들지 마라.
- 편집 가능한 원본이 필요하면 함께 보존하고, 제출 형식은 담당 기관 요구를 따르라.

## 예시 도면의 사실성

입력 좌표·배치와 결과 관계가 본문과 맞는지 검산하라. 서로 양립하지 않는 사례를 하나의 실제 공간처럼 합치지 마라. 별도 사례면 패널을 분리하고 독립 예시라고 표시하라. 부분 그래프라면 일부 노드·방향·관계를 생략했다는 점을 밝히고, 생략이 곧 관계 부재라고 읽히지 않게 하라.

가상 배치, 실제 실행 결과, 개념도를 명확히 구분하라. 실제 출력으로 제시하려면 동일 실행의 입력·설정·출력을 확보하라.

## 완료 점검

그림을 렌더링하여 잘림·겹침·글꼴·화살표·캡션 위치를 보라. 도면 변경 시 본문 도면 설명, 번호, 부호, 관련 예제, 청구항 참조를 확인하라. 단순 도면 수정 요청을 기술 범위 변경으로 확대하지 마라.
