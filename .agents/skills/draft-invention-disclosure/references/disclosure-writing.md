# 발명신고서 본문 양식과 문체

## 기본 목차

기관 서식이 있으면 그 서식을 우선하고 아래 항목을 대응시켜 채워라. 이는 작성용 기본안이며 법정 공통 양식으로 제시하지 마라.

| 항목 | 담을 내용 | 주의점 |
|---|---|---|
| 발명의 명칭 | 대상과 핵심 작동을 드러내는 기술 명칭 | 과장된 성능·제품명·포괄적 유행어 회피 |
| 기술 요약 | 문제, 해결 수단, 결과를 한 단락으로 | 본문에서 설명하지 않은 구성 추가 금지 |
| 기술 분야·적용 대상 | 다루는 데이터·장치·상황·입력 전제 | 분야 전체를 구현 범위로 오해하지 않게 작성 |
| 종래 기술과 한계 | 기존 방식, 그 방식이 실패하거나 비효율적인 조건 | 조사 없이 최초·유일·기존 기술 부재 단정 금지 |
| 해결 과제 | 이번 발명이 해결하려는 구체적 문제 | 후속 연구 목표와 구분 |
| 발명의 구성·작동 | 구성 간 연결, 처리 단계, 조건, 출력 | 기능명 나열 대신 어떻게 작동하는지 설명 |
| 차별화 요소 | 비교 대상과 다른 처리 및 그 이유 | 선행기술을 조사하지 않았다면 차별화 후보로 표시 |
| 실시예·변형예 | 입력·조건·중간 결과·최종 결과, 대체 가능한 구성 | 구현 확인·구상·가상 예제를 구별 |
| 발명의 효과 | 특정 처리로부터 생기는 기술적 효과 | 측정되지 않은 비율이나 성능 보장 금지 |
| 도면과 설명 | 번호, 도면 목적, 본문 대응 | 그림만 보고 핵심 연결 이해 가능하게 |
| 활용·사업화 가능성 | 적용 상황과 사용자, 현실적인 활용 | 필수 기술 구성과 시장 전망을 혼합하지 않기 |
| 행정 정보 | 발명자 기여, 소속, 관련 과제, 공개·출원 이력 등 서식 요구사항 | 누락은 확인 필요로 표시, 개인정보 추정 금지 |

## 문장 구조

한국어 서술형 문장으로 쓰고 한 문단에 하나의 역할을 부여하라. 신고서는 연구 내용을 담당자가 이해할 수 있는 수준으로 쓰며, 청구항 특유의 긴 열거문이나 ‘상기’를 과하게 사용하지 마라. 명세서로 확장할 때 필요한 용어와 문단 번호 체계를 적용하라.

- 문제: “기존 방식은 [처리]를 수행하지만, [상황]에서는 [원인] 때문에 [문제]가 발생할 수 있다.”
- 수단: “[처리부/단계]는 [입력]에서 [대상]을 선택하고, [조건]에 따라 [처리]하여 [결과]를 생성한다.”
- 효과: “[수단]을 적용함으로써 [원인]을 줄여 [기술적 결과]에 기여할 수 있다.”
- 변형예: “다른 실시예에서는 [대체 수단]을 적용할 수 있다. 이 경우 [전제와 차이]를 갖는다.”

‘효율적으로 처리한다’, ‘정확도를 향상한다’로 끝내지 말고 비교 대상·작동 원리를 연결하라. ‘할 수 있다’를 모든 필수 단계에 붙여 발명의 중심이 사라지지 않게 하라. 반대로 특정 라이브러리·저장 방식·임계값을 특별한 이유 없이 필수로 만들지 마라.

용어는 최초 등장 시 뜻과 필요한 약어를 제시하고 일관되게 사용하라. 의미적 소속과 기하적 포함, 근사 거리와 실제 표면 거리, 후보 생성과 확정 판정처럼 결과 의미가 다른 용어를 합치지 마라. 실제 작동과 명칭이 다르면 정의를 바로잡고 변경 이유를 남겨라.

## 구체화 깊이

각 핵심 절차에 아래 질문이 답해질 정도로 작성하라.
1. 어떤 입력 정보와 전제가 필요한가?
2. 어떤 대상을 어떤 기준으로 고르는가?
3. 무엇을 계산·변환·비교하는가?
4. 조건을 만족하거나 만족하지 않으면 어떻게 되는가?
5. 결과는 어떤 구조·속성으로 저장되거나 다음 단계에 전달되는가?

수식은 변수 정의, 단위, 적용 가능한 입력, 분모 0 등 경계 조건을 함께 써라. 임계값은 범위 또는 예시인지 고정 요구인지 구별하라. 가상 예제는 동일한 입력·설정에서 결과가 논리적으로 일치하도록 계산하고 실험 결과로 부르지 마라.

## 문서 외형

기존 양식이 없으면 A4, 읽기 쉬운 한글 글꼴, 일관된 제목 단계, 충분한 여백을 사용하라. 분량을 맞추기 위해 글자를 과도하게 줄이지 마라. 표는 구성 대응·비교·근거 정리에 사용하고 본문 전체를 표로 대체하지 마라. 도면 캡션과 그림, 표 제목과 표가 페이지 경계에서 분리되지 않게 하라.

검토본에서는 본문과 내부 검토 메모를 구분하라. 제출용 정리 요청 시 검토 표지·작업 이력·확인 필요 메모를 별첨으로 분리하고 남겨야 할 사실 확인 사항을 숨기지 마라.
