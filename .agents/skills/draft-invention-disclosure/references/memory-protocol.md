# 공통 연구 기억 운영 규칙

버전: 1.0.0 / 2026-10-12

## 기준 저장소와 정보의 우선순위

- Git 저장소의 스킬·규칙은 작업 방법의 원본이다. 현재 연구 상태·가설·결정·세션은 Notion을 기준으로 한다. 코드 동작과 수치는 실제 commit/config/run/원문으로 확인한다.
- 최신 사용자 결정은 기존 운영 결정보다 우선한다. 경험적 사실은 직접 확인한 근거를 우선하며, 최신 문서라는 이유만으로 사실로 승격하지 않는다.
- 세션은 작업 기록이다. 논문·실험 전체 근거를 대체하지 않는다. 원문 전체나 비공개 사고과정 대신 재현 가능한 결론·근거·미해결·다음 행동을 저장한다.
- 공개 Git에는 미공개 연구, 특허 구성, 개인 Notion URL/ID, 자격증명, 원본 데이터와 대화 원문을 넣지 않는다. 개인 연결 정보는 `*.local.json`, 임시 미저장 기록은 `private/`에 둔다.

## 세션 시작

1. 현재 요청의 프로젝트를 확인한다. 다른 논문·표준화·특허·센서 과제의 결정을 서로 섞지 않는다. 관련 없는 일반 질의에는 연구 기억 전체를 불러오지 않는다.
2. [기억 위치](memory-location.md)에 따라 실제 연결 설정을 읽고, 해당 프로젝트의 Research State를 fetch한다. 설정이 없으면 과거 대화/일반 메모리는 보조로만 사용하고 최신 상태를 확인했다고 말하지 않는다.
3. 관련 Accepted 결정과 최근 관련 세션 1~3개를 찾아 필요한 내용만 읽는다. 과거로 거슬러 올라갈 필요가 있을 때만 범위를 넓힌다.
4. 읽은 상태의 version/last_edited_at, 근거 출처, 사용 스킬 버전을 기록한다. Notion 사용 시 현재 도구 스키마를 확인하며 API 이름을 고정 추측하지 않는다.

## 작업 중과 마무리

1. 의미 있는 결정·실험·설계 변경 시 checkpoint를 남긴다. 정상 종료 순간에만 의존하지 않는다. 세션 ID는 날짜/호스트/UUID 등 충돌하지 않는 값으로 생성한다.
2. `Observed`(직접 확인), `Reported`(사용자 보고), `Proposed`(AI 제안), `Accepted`(명시적 사용자 채택), `Unresolved`를 구분한다. 침묵이나 다음 주제로 이동한 것을 동의로 취급하지 않는다.
3. 먼저 자신의 AI Sessions 항목을 저장한다: Project, Session ID, 시각, Agent, 목적, 수행 내용, 결과와 근거, 결정/가설, 미해결, Next Action, 실제 commit/run. 결과가 불확실하면 같은 ID를 검색한 뒤 재시도하여 중복을 막는다.
4. 중요한 결정은 Decisions에 Decision ID, 상태, 채택 주체/근거, 대안, 위험, 반전 조건, 다음 행동과 이전 결정 ID를 남긴다. 과거 결정을 삭제하지 말고 Superseded로 연결한다.
5. Research State를 다시 읽은 뒤 바뀐 절만 최소 수정하고 version을 증가시킨다. 다른 세션의 변경이 있으면 병합한다. 충돌이 해결되지 않으면 자신의 세션을 Pending sync로 남기고 현재 상태를 덮어쓰지 않는다. Notion의 원자적 잠금을 가정하지 않는다.
6. 저장 후 결과 ID/URL과 수정 내용을 확인한다. Git, ChatGPT 설치 스킬, Notion, 사용자 PC 적용을 각각 구분하여 보고한다. 한 곳 성공을 전체 동기화 완료로 말하지 않는다.

## 장애와 권한

- Notion 불가: 유용한 작업은 계속하되 최신 상태 미확인을 알린다. 허용된 로컬 `private/pending/`에 동일 세션 ID로 보존하거나 답변에 인계 기록을 남기고, 복구 후 기존 ID를 조회해 반영한다. 공개 Git으로 우회 저장하지 않는다.
- Git push 실패: 로컬 변경·commit을 보존하고 원격 미반영을 알린다. force push, reset --hard, credential 탐색을 하지 않는다. branch 보호가 있으면 허용되는 PR 경로를 사용한다.
- 연결 도구·권한은 호스트가 실제 제공한 범위만 사용한다. 이 문서는 권한, 백그라운드 실행, 타인 연락, 논문 제출을 새로 부여하지 않는다.
- 저장·동기화는 활성 작업 중의 절차다. 이 스킬 자체가 대화 밖 상시 감시자나 무인 동기화 서비스가 되지는 않는다.

## 스킬 변경

연구 상태의 변경만으로 SKILL.md를 매번 바꾸지 않는다. 반복 사용할 작업 방법·평가 원칙·사용자 협업 선호가 바뀔 때만 스킬 원본을 수정한다. Git 원본의 최신 버전과 설치 사본을 비교하고 양쪽 변경이 있으면 병합한다. 기존 name과 설치 ID를 유지한다. 상세 배포 절차는 저장소의 docs/SYNC.md를 따른다.
